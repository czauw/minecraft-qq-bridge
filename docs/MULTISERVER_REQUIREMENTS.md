# 功能契约与验收条件

本文件是 QQ 官方机器人 × QueQiao 多服务器互通的实现契约，优先于早期研究中的缩减范围
（旧 `/mc`、只做文档、OneBot 优先均不适用）。

## 必须实现

1. QQ 侧只用官方 API（无非官方登录依赖）；每台服务器一条独立 QueQiao WebSocket 客户端；
   配置 / QQ / QueQiao / 路由 / 管理分层。
2. YAML 全字段中文注释；`bot.app_id`、`client_secret`（允许安全环境变量引用）、`group_openid`；
   每个 server 的 `name`/`host`/`port`/`enabled`（默认 true）与 `path`、认证等。`name` 唯一、
   `host+port` 唯一（同 host 不同 port、不同 host 同 port 合法）；禁用项保留配置但不连接/广播/查询；独立重连。
3. 列表指令按配置顺序查询所有**启用**服务器（`enabled: false` 不查询、不出现在结果里，
   按名字查回「未找到服务器：X」）：

   | 情形 | 文本 |
   |---|---|
   | 有玩家 | `名称 N人在线：` 后逐行玩家名 |
   | 零人 | `名称 0人在线` |
   | 离线 | `名称 离线` |
   | 名称不存在 | `未找到服务器：名称` |
   | 结果为空 | `没有启用的服务器` |

   多服务器用空行分隔，指令不转发 MC。**边界**：零启用服务器在 CLI 层就无法启动（退出码 2），
   「没有启用的服务器」只是路由层空结果文案。名单来自 QueQiao 权威接口；启动/重连同步、join/leave 增量、
   断线失效、单服异常隔离、人数与列表一致。
4. 仅目标群的 QQ 消息广播至所有启用且在线的服务器，文本「群员昵称：消息内容」；图片 `[图片]`、
   其它附件 `[附件]`，不下载；过滤机器人自身、重复事件与斜杠消息；单服失败隔离。
   昵称优先官方 `author.username`，缺失时用可配置 fallback，不编造昵称或顺序保证。
5. MC `chat`/`join`/`leave`/`death` 转发 QQ：`[服务器名称] [玩家ID] ： 内容`；join「进入了服务器」、
   leave「离开了服务器」、死亡保留原始原因；同名玩家可区分服务器；未知事件忽略、重复去重、回环抑制。
6. 每服独立连接，断线立即离线，自动退避重连并重新同步；错误/未知包、查询、发送失败隔离；
   启动/停止/连接/断开/重连/发送失败/解析失败有可读日志，密钥不进入日志。
7. 官方 token 获取与刷新、Gateway 心跳/Resume/重连、关闭码分流、权限/配额限流按官方文档实现；
   全量接收与主动推送在官方权限内工作，不绕过、不把权限问题误报成功。

## 指令与消息预处理

* 全量模式（`GROUP_MESSAGE_CREATE`）正文开头的 `<@member_openid>` / `<@!...>` 标签必须先剥离再匹配指令；
  转发 MC 的文本也不含该前缀。只处理开头连续的标签，不动正文中间的内容。
* 列表指令默认 `/list`，可由 `relay.list_command` 改成其它 `/xxx`（大小写不敏感，`/listing` 不算）。
* 所有以 `/` 开头的聊天一律不转发到 MC；未实现的斜杠指令（如 `/help`）只被丢弃，**不保证有回复**。
* 机器人自身消息（`author.bot=true`）不处理；非目标群、私聊、频道事件忽略。

## 交付

可运行代码、中文注释 YAML 模板（不含真实密钥）、固定/有界依赖、简洁启动入口、面向普通用户的中文 README
（环境与安装、机器人准备、`group_openid` 获取、QueQiao 准备与版本、启动、全部配置字段、多服/禁用、
功能示例、失败排查）、测试与验证报告（明确模拟与真实验证边界）。

## 验收场景

三服独立连接；同 IP 不同端口、不同 IP 同端口唯一性；禁用不连接；列表指令全部/单个；
在线/零人/离线/未找到；QQ 广播与多图片；MC 四事件及同名玩家来源；单服断线隔离、自动重连、重同步；
去重/回环；普通用户按 README 可部署。必须用真实执行的协议模拟/集成测试覆盖；有真实权限时再做联通，
没有外部条件则明确不可实测，不假称真实验收完成。
