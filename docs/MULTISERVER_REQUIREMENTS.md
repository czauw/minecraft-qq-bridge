# 本轮交付要求与负责人约束

用户要求在 /home/czauw/minecraft-qq-bridge 现有项目上实现 QQ 官方机器人 × Minecraft QueQiao 多服务器互通。此文是本轮验收契约，优先于旧研究中的缩减范围（旧 /mc、只做文档、OneBot 优先均不适用）。

## 协作
负责人仅管理看板、手动分配 planner → worker → reviewer，阻塞时评论协调修复。使用已配置 profiles，不启用 expert 除非普通角色已证实无法解决具体难题。不自行创建/分发新卡，由负责人统一创建。所有任务实际工作目录为本项目。保留现有 untracked 文件，不 reset/clean、不擅自提交/发布。不得读取/打印凭据；真实配置只按安全方式引用。开发、测试、文档自动推进，缺外部平台权限不能伪造通过。完成后负责人通过 default QQ 机器人通知用户。

## 必须实现
1. QQ 侧仅官方 API（无非官方 QQ 登录依赖），QueQiao WebSocket 客户端；模块化配置/QQ/QueQiao/路由/管理。
2. YAML 全字段中文注释，bot app_id、client_secret（允许安全环境变量引用）、group_id（实际 group_openid）、官方运行必要参数。每个 server name/host/port/enabled（默认 true），按协议补充 path、认证等。host+port 唯一、name 唯一；相同 host 不同 port 或不同 host 相同 port 均合法；禁用保留但绝不连接/监听/广播；独立重连。
3. /list 按配置顺序查询所有**启用**服务器（`enabled: false` 的既不查询也不出现在结果里，按名字查回“未找到服务器”），/list 名称查询单个。格式：名称 N人在线：后逐行玩家；零人“名称 0人在线”；离线“名称 离线”；不存在“未找到服务器：名称”；无启用服务器时“没有启用的服务器”。多服务器空行隔开，命令不转发 MC；所有以 `/` 开头的聊天都不转发。实时玩家名单来自 QueQiao 权威接口，启动/重连同步已有玩家，join/leave 更新，断线失效，单服查询异常不影响其他服，人数与列表一致。
4. 仅目标群 QQ 消息广播至所有启用且在线服务器；格式“群员昵称：消息内容”；图片替换 [图片]，多图片尽量保持位置；不下载图片。过滤机器人自身、重复事件及 /list；单服失败隔离。核实官方 nickname/消息顺序能力，缺失时采用明确文档化可配置 fallback，不能编造昵称或顺序保证。
5. MC chat/join/leave/death 转发目标 QQ：统一 “[服务器名称] [玩家ID] ： 内容”；join 内容“进入了服务器”、leave“离开了服务器”；死亡保留原始原因；同名玩家可区分服务器；未知事件忽略、重复去重、QQ↔MC 回环防止。
6. 每服独立连接、断线立即离线、自动退避重连、重连重同步；错误包/未知包/查询/发送失败隔离；启动/停止/加载/连接/断开/重连/发送失败/解析失败有可读日志，密钥不进入日志。
7. 官方 token 获取更新、Gateway 心跳/恢复/重连、权限/配额/限流等按实际官方文档实现。全量群消息和主动 MC 通知按官方权限可用范围工作，不用非官方协议绕过，不把权限问题误报成功。

## 交付
完整可运行代码、中文注释 YAML 实际配置/安全模板（不含真实密钥）、固定/有界版本依赖、简洁启动入口、独立面向普通用户的中文 README。README 包括环境/安装依赖、官方机器人准备、QueQiao 安装准备及支持版本、启动、每个配置字段、group_openid 获取、添加多服/禁用、全部功能示例、启动失败/QQ 接收权限/连接离线/名单错误/转发失败 FAQ。更新旧启动 Docker/Makefile 等避免用户误启动旧 OneBot。提供测试和验收报告，明确模拟与真实验证边界。

## 验收场景
三服务器独立连接；同 IP 不同端口、不同 IP 同端口唯一性；禁用不连接；/list 全部/单个；在线/零人/离线/未启用；QQ 普通广播和多图片；MC 四事件及同名玩家来源；单服断线隔离、自动重连、重同步；去重/回环；普通用户按 README 可部署。必须用真实执行的协议模拟服务器/集成测试覆盖，在具备真实配置权限时再做真实联通；没有外部条件则明确不可实测，不假称全部真实验收完成。
